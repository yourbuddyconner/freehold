Quickstart

This guide walks from a clean machine to a running Freehold daemon with an agent connected. The two prerequisites — a sibling Allod checkout and a one-time WASM build — are the main things to get right before anything else.

Prerequisites

Freehold consumes @allod/core, a WASM npm package built from the Allod source. The package is not yet published to npm; it is consumed from a sibling checkout on disk. This means you need both repos.

  • Node ≥ 22 — the daemon uses Node for the runtime
  • pnpm — the workspace package manager (pnpm.io)
  • Rust + wasm-pack — required once to build the Allod WASM package; not needed after that unless you update Allod

Install wasm-pack if you do not already have it:

cargo install wasm-pack

Install and build

Both repositories must be siblings in the same parent directory. The name matters: Freehold's workspace configuration resolves @allod/core as ../allod/crates/allod-wasm/pkg.

# 1. Clone both repos as siblings — order does not matter
git clone https://github.com/yourbuddyconner/allod
git clone https://github.com/yourbuddyconner/freehold

# Your directory should look like:
#   some-parent/
#     allod/
#     freehold/

# 2. Build the Allod wasm package (one time)
cd allod/crates/allod-wasm
pnpm install
pnpm build
cd ../../..

# 3. Install Freehold dependencies
cd freehold
pnpm install

Start the daemon

pnpm --dir packages/api exec tsx src/cli/index.ts serve

The daemon binds 127.0.0.1:8710, creates ~/.freehold/ on first run (config, the PGlite index directory, and your graph in native Allod layout), and serves the owner console at http://127.0.0.1:8710.

A bearer token is auto-minted into ~/.freehold/config.json (mode 0600) at first boot. The CLI and the MCP config use this token automatically.

Run from source for semantic recall. The compiled binary ships with a hash embedder only — semantic recall (bge-small cosine similarity) is unavailable in the binary build. For development and dogfood use, run from source via tsx as shown above. Recall still functions with the hash embedder (BM25 full-text + hash vectors), but semantic similarity is not available.

Wire an agent

With the daemon running, wire an agent from a second terminal:

# Write the MCP config entry for Claude Code
freehold mcp setup claude-code

# Or print config JSON for any other agent
freehold mcp setup --print

The config points the agent at http://127.0.0.1:8710/mcp (streamable HTTP MCP) with the bearer token from ~/.freehold/config.json.

Then open the console in your browser at http://127.0.0.1:8710 and watch the Inbox as the agent works. Scratch notes appear in Memory immediately. Consequential writes — preferences about you, entities outside the scratch region — appear in the Inbox as proposals for you to approve or reject.

Try the memory loop

From your agent (Claude Code or any MCP client):

# Fast scratch note — admitted immediately
remember("Meeting with design team at 2pm")

# Governed write — will be held for approval
create_entity("memory/Preference", {
  content: "prefers morning meetings",
  strength: "strong"
})

The second call returns { status: "held", proposal, rule }. The proposal appears in your Inbox with the agent's identity, the diff, and the rule that held it. Approve it to admit the write and sign a decision record.

Try the schema loop

# Read what the graph already knows
describe_schema()

# Propose a new type when the graph lacks one
propose_ontology_change({
  kind: "add_entity_type",
  name: "Colleague",
  extends: "core/Person",
  attributes: [{ name: "slack_id", type: "string", required: false }]
})

Schema proposals are always held. Approve the proposal in the Inbox to install the type. The Schema viewer in the console will show the new type with its provenance — which agent proposed it, which changeset added it, your signature on the approval.

CLI reference

freehold serve runs the product. Every other subcommand is a client of the running daemon over its public HTTP API:

Command Description
freehold statusCheck if the daemon is running and report its state
freehold remember <text>Write a scratch note from the command line
freehold recall <query>Search memory and print results
freehold pendingList proposals awaiting approval
freehold approve <hash>Approve a proposal by its changeset hash
freehold reject <hash>Reject a proposal; records a signed rejection
freehold verifyRun three-level graph verification
freehold reindexRebuild the PGlite index from the graph log
freehold mcp setup <agent>Write the MCP config entry for a named agent
freehold mcp setup --printPrint MCP config JSON for any agent

All commands accept --json for machine-readable output. Exit codes: 0 ok, 2 held, 3 policy-rejected, 4 auth, 5 daemon unreachable.

Known limitations (v0)

  • Semantic recall unavailable in the compiled binary. The binary ships with hash-embedder only. Run from source via tsx for semantic (cosine similarity) search over bge-small embeddings. See F10-deferred for the technical details and planned resolution.
  • Sidecar files required for the compiled binary. The binary requires four sidecar files in the same directory (PGlite WASM engine, FS bundle, initdb WASM, pgvector extension bundle). The compile-binary.mjs script copies these automatically.
  • Single-user, local-only. The daemon binds 127.0.0.1. Multi-user, remote instances, and federation between Freehold instances are out of scope for v0.
  • No memory graph visualization. The force-directed graph view is deferred to v0.1.
