Your agents' memory,
in a graph you own.

Freehold is a memory server for AI agents that runs on your machine. Agents connect over MCP and save what they learn as they work. Quick notes save instantly. Anything important — a preference about you, a change to how memory is organized — waits in your inbox until you approve it. Every decision is signed with your key, and the whole history can be verified with open tools.

Why Freehold

What you get

01

It runs on your machine

Freehold is a single daemon on your laptop. Memory lives in ~/.freehold as an append-only log of signed changes in the open Allod format, and the console, the API, and the MCP endpoint all serve from one local port. There is no cloud service and no account.

How it's built
02

You approve what matters

Agents save quick notes instantly. Writes that change what memory says about you — preferences, facts about people, new entity types — go to your inbox as proposals, and nothing important lands until you approve it. Agents can propose changes to memory's own schema through the same inbox.

How approval works
03

You can check everything

Approvals and rejections are records signed with your key, stored in the same log as the memory itself. The independent allod verify command checks the whole history — hashes, signatures, and decisions — without running Freehold at all, so you never have to take Freehold's word for it.

How it works

From agent write to signed record

Here is what happens when an agent tries to save something important.

Step 01

The agent writes

The agent calls create_entity with a memory/Preference: "prefers morning meetings". A quick note would save instantly; a preference goes through the policy rules first.

note → saves instantly
Step 02

Policy pauses it

The write matches a rule — preferences about you need your approval — so it becomes a proposal. The agent gets { status: "pending", proposal, rule } and moves on.

pending
Step 03

You decide

The proposal appears in your inbox with the agent's name, what it wants to save, the diff, and the rule that stopped it. You approve or reject it in one click.

approved
Step 04

The decision is signed

Approving signs a decision record with your key and saves the write. From then on it comes back in recall with its history attached: who wrote it, who approved it, and the changeset hash.

verified
Quickstart

Up in four commands

Prerequisites: Node ≥ 22, pnpm, and Rust with wasm-pack (for the one-time Allod WASM build). Both repos must be siblings on disk.

bash 
# 1. Clone both repos as siblings
git clone https://github.com/yourbuddyconner/allod
git clone https://github.com/yourbuddyconner/freehold

# 2. Build the Allod wasm package (one time)
cd allod/crates/allod-wasm && pnpm install && pnpm build && cd ../../..

# 3. Install dependencies and start the daemon
cd freehold && pnpm install
pnpm --dir packages/api exec tsx src/cli/index.ts serve
# Binds 127.0.0.1:8710 — console at http://127.0.0.1:8710

# 4. Wire an agent
freehold mcp setup claude-code   # writes the MCP config entry
freehold mcp setup --print        # or print JSON for any other agent

MCP tools

Twelve tools for agents

Agents get exactly these tools over MCP. Approving, rejecting, and policy changes are not agent tools — those happen in your console and CLI.

Knowledge
remember
Save a quick note. Creates a memory/Note and saves it instantly. Sugar over create_entity.
Knowledge
create_entity
Create a typed entity, with optional classifications and edges, in one atomic change.
Knowledge
update_entity
Revise an entity's attributes, checked against its current revision so updates can't silently collide.
Knowledge
relate
Create a typed edge between two entities. Time lives on the edge (from/until).
Knowledge
classify
Place an entity in the taxonomy. Classification decides which policy rules apply, so this write can end up pending.
Knowledge
attach_document
Store source material by content hash, so claims can cite the exact bytes they came from.
Retrieval
recall
Semantic plus full-text search. Filter by type, author, or approval status. Every result says who wrote it and who approved it.
Retrieval
get_entity
One entity in full: attributes, classifications, edges, revision history, and who approved what.
Retrieval
traverse
Walk the graph from a starting entity, following typed edges up to a chosen depth.
Retrieval
pending_approvals
The agent's own writes that are waiting for your approval.
Schema
describe_schema
Read the installed entity types, edge types, and taxonomy — straight from the graph.
Schema
propose_ontology_change
Propose a new type or term. Always needs your approval before it is installed.
