Your agents' memory, in a graph you own.

Freehold gives every agent you run one shared, persistent memory on your machine. Sessions start with context instead of a blank slate, anything important waits for your approval, and you can trace every belief back to the moment you approved it.

What changes

When your agents get a memory you govern

Agents forget everything between sessions, and the usual fix is letting them write whatever they infer into a store you can't see. Freehold changes both.

01

Sessions start with context

Every agent you run shares one memory over MCP. Tell one agent you prefer short PRs and rebase merges, and the next session — and every other agent — already knows. Notes, preferences, people, and project facts accumulate instead of evaporating.

How agents recall
02

You decide what becomes true

Anything that would change what memory says about you — a preference, a fact about a person, a new schema type — waits in your inbox as a proposal. A bad inference ends as a rejected proposal, and the record shows it was never believed.

How approval works
03

Every belief has a paper trail

Ask "why does it think that?" and get an answer: who wrote it, which rule caught it, who approved it, in which changeset. The history is signed, lives on your disk, and the independent allod verify command checks it without Freehold.

How signatures work
Use cases

What you can do with it

A coding agent that knows how you work

Your conventions, review preferences, deploy rituals, and the people on your team. Approve them once, and every session starts there instead of you re-explaining — no more pasting the same context into every project.

Overnight agents with a morning review

An agent that works while you sleep saves its notes freely, and its important conclusions queue as proposals. Your inbox is the morning diff of what it wants you to believe — approve the good, reject the hallucinated.

One brain across all your tools

Claude Code, a custom agent, a script with an MCP client: all of them read and write the same graph under the same rules. What one learns, the others know, and none of them can bypass your approval.

Memory you can audit

Every attempt is in the log, including the rejected ones. When an agent misbehaves, you can see exactly what it tried to save, when, and what you allowed — signed, timestamped, and checkable with an independent tool.

How it works

From agent write to signed record

What happens when an agent tries to save something important.

Step 01

An agent writes

The agent calls create_entity with a memory/Preference: "prefers morning meetings". Notes save instantly; a preference goes to the policy rules first.

note → saves instantly
Step 02

Policy makes it a proposal

The write matches a rule: preferences about you need your approval. The agent gets { status: "pending", proposal, rule } and moves on.

pending
Step 03

You decide

The proposal shows up in your inbox with the agent's name, the diff, and the rule that matched. One click to approve or reject.

approved
Step 04

Signed and saved

Your approval is a decision record signed with your key. The preference is saved, indexed, and comes back in recall with its full history.

verified
Quickstart

Up in three commands

Prerequisites: Node ≥ 22 and pnpm. No Rust toolchain — the Allod engine ships prebuilt.

bash 
# 1. Clone and install — @allod/core comes prebuilt from GitHub releases
git clone https://github.com/yourbuddyconner/freehold
cd freehold && pnpm install

# 2. Start Freehold
pnpm --dir packages/api exec tsx src/cli/index.ts serve
# Binds 127.0.0.1:8710 — console at http://127.0.0.1:8710

# 3. Wire an agent
freehold mcp setup claude-code   # writes the MCP config entry
freehold mcp setup --print        # or print JSON for any other agent

MCP tools

Twelve tools for agents

Agents get exactly these tools over MCP. Approving, rejecting, and policy changes are yours alone — they happen in the console and the CLI.

Knowledge
remember
Save a quick note. Creates a memory/Note and saves it instantly. Sugar over create_entity.
Knowledge
create_entity
Create a typed entity, with optional classifications and edges, in one atomic change.
Knowledge
update_entity
Revise an entity's attributes, checked against its current revision so updates can't silently collide.
Knowledge
relate
Create a typed edge between two entities. Time lives on the edge (from/until).
Knowledge
classify
Place an entity in the taxonomy. Classification decides which policy rules apply, so this write can end up pending.
Knowledge
attach_document
Store source material by content hash, so claims can cite the exact bytes they came from.
Retrieval
recall
Semantic plus full-text search. Filter by type, author, or approval status. Every result says who wrote it and who approved it.
Retrieval
get_entity
One entity in full: attributes, classifications, edges, revision history, and who approved what.
Retrieval
traverse
Walk the graph from a starting entity, following typed edges up to a chosen depth.
Retrieval
pending_approvals
The agent's own writes that are waiting for your approval.
Schema
describe_schema
Read the installed entity types, edge types, and taxonomy — straight from the graph.
Schema
propose_ontology_change
Propose a new type or term. Always needs your approval before it is installed.
