# M4 Git-Proposal Inbox Implementation Plan (sub-project 3 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repo graphs' Inbox lists undecided commits as proposals with per-role checklists and region badges; deciding signs a decision record through the key backend into `refs/notes/allod-decisions` (auto-push per graph setting); reviews and path-anchored comments store as native nodes.

**Architecture:** A `gitreview.ts` core module enumerates branch heads via git.ts, evaluates each commit with the wasm bindings (`git_checklist`, `git_satisfaction`) plus git-computed ops and note-read decisions, and decides via the two-phase seam (`git_decision_payload` → keys.ts sign → `git_decision_attach` → `appendDecision` → optional `pushNotes`). Review artifacts are ordinary native nodes (`review/Review@1`, `review/ReviewComment@1` + `part_of` edges) written through the existing commit flow. API routes under the scoped mount; the web Inbox gains git-proposal cards for repo graphs.

**Tech Stack:** TypeScript, @allod/core wasm bindings, git CLI via execFile, keys.ts (file/keychain), Hono, React, vitest.

Spec: `docs/specs/2026-08-04-governed-review-surface-design.md` (sub-project 3 section).

## Global Constraints

- No registration step: per §3.3 the commit IS the proposal — the Inbox is a view over refs × decisions. Never write graph state to enumerate.
- No policy logic in TypeScript: checklist/satisfaction come only from wasm (`git_checklist`, `git_satisfaction`); decision records only from `git_decision_payload`/`git_decision_attach`. freehold supplies only bytes git can produce (ops, shas, note contents).
- Signing goes through `keys.ts` (`resolveKey`/`signPayload`) with the graph's `allodGraphId` and `repoDir` for the legacy fallback — Touch ID prompts happen at decide time when the key is in the keychain. Missing key → typed error surfaced as governance-actions-disabled-with-reason, never a crash.
- Decisions append to `refs/notes/allod-decisions` via git.ts `appendDecision` (byte-compatible with `allod git decide`); auto-push via `pushNotes` when the graph entry's `autoPushNotes` is true AND `originRemote` exists; push failure → decision stays local with a visible retry (saved-locally state), never silent.
- Stale-derivation honesty: diff paths with no SourceFile node are labeled not-yet-indexed with `allod git index` guidance, never silently reachless.
- Vocabulary: approved/rejected/incomplete for decide outcomes; saved/pending for writes. Never "admitted"/"held" in UI/API strings.
- All wasm access through withGraph. Engine facts (SP1 ledger): review-node endpoints must be admitted before edges; typed cross-ontology targets need their ontologies installed — v1 review artifacts use ONLY `review/Review` (attributes verdict/body/commit — commit holds the sha) and `review/ReviewComment` + `part_of`/`replies_to` edges; the `reviews`/`concerns` edges are NOT created in v1 (targets need eng/code nodes that may not exist).
- Reject records verdict `reject` the same signed way (allod's guard: a rejected sha stays decided — surface it as rejected, not undecided).
- Suite: root `pnpm test` green; web tsc force-check + build green.

```ts
// git.ts addition
export async function branchHeads(repoDir: string): Promise<Array<{ ref: string; sha: string }>>;
// git for-each-ref refs/heads --format=%(refname)%09%(objectname)

// gitreview.ts
export interface GitProposal {
  sha: string; ref: string; author: string; timestamp: string; message: string;
  target: string;                       // the ref evaluated against, e.g. refs/heads/main
  matched: string[];                    // rule names
  checklist: unknown[];                 // wasm checklist entries (role requirements) as returned
  unmet: string[];                      // from git_satisfaction with current note decisions
  decided: "undecided" | "approved" | "rejected";
  paths: Array<{ verb: string; path: string; regions: string[]; indexed: boolean }>;
}
export async function listGitProposals(fh: Freehold): Promise<GitProposal[]>;
// branch heads + the checkout's HEAD; skip shas already decided approve (decided !== undecided still listed
// with their status so the Inbox can show recent outcomes — LIST ALL heads' tips, mark decided state).
// Evaluation per sha: diffTreeOps → withGraph git_checklist(basename(fh.graphDir), ref, ops) →
// readDecisions → git_satisfaction("git:<sha>", checklist, decisions) → unmet.
// paths[].regions from the checklist's matched region rules for that path (ask git_checklist per-sha once;
// per-path region badges reuse codeRegions(fh, repoName) — a path is in-region if any RegionRule.paths contains it).
// paths[].indexed = SourceFile node exists (reuse codeFile != null or a cheaper path-set query).

export async function gitProposal(fh: Freehold, sha: string): Promise<GitProposal | null>;
// same shape for a single sha (resolve via commitMeta; null if the sha is unknown to git).

export type DecideResult =
  | { outcome: "approved" | "rejected"; pushed: boolean; pushError?: string }
  | { outcome: "incomplete"; unmet: string[] };
export async function decideGit(
  fh: Freehold, sha: string, verdict: "approve" | "reject", principal: string,
  entry: { allodGraphId: string; autoPushNotes: boolean; originRemote: string | null },
): Promise<DecideResult>;
// 1. wasm git_decision_payload("git:<sha>", verdict) → {record, payload}
// 2. keys.resolveKey(entry.allodGraphId, principal, { repoDir: fh.graphDir }) — a resolve failure throws
//    KeyMissingError (define: class KeyMissingError extends Error { code = "key-missing" }) with the searched
//    locations in the message.
// 3. keys.signPayload → git_decision_attach(record, principal, sig)
// 4. appendDecision(fh.graphDir, sha, signedRecord)
// 5. re-evaluate satisfaction with the new decisions: unmet non-empty AND verdict approve → outcome "incomplete"
//    (the decision is still recorded — mirrors allod's StillUnmet).
// 6. autoPushNotes && originRemote → pushNotes; a push failure returns pushed:false + pushError (decision saved locally).
```

Test fixture: scripted git repo (git init, commits on main + a feature branch touching `src/lib.rs`) combined with the codeview-style graph fixture (code ontology + SourceFile/Function nodes + a policy whose rule binds `repo: <basename>` with a reviewer role bound to a principal whose key the test writes via `ALLOD_KEYS_DIR` — the keys.test.ts helper shape). Tests:
- `branchHeads` lists main + feature with correct shas.
- `listGitProposals`: both tips present; the feature commit touching the governed path has the rule in `matched`, non-empty `unmet`, `decided: "undecided"`; paths carry `indexed: true` for the SourceFile path and `indexed: false` for a path with no node; region badges present for the in-region path.
- `decideGit` approve with the role-bound principal: outcome approved, note readable via `readDecisions` and byte-shape has kind/subject/`deciders[0].signature` `sig:ed25519:`; re-list shows `decided: "approved"` and empty unmet.
- `decideGit` with an unbound principal whose key exists → outcome incomplete with unmet (decision recorded).
- `decideGit` with a principal that has NO key → throws KeyMissingError (assert code).
- reject path → decided: "rejected" on re-list.
- Push behavior: with a local bare remote as origin and autoPushNotes true, the notes ref appears on the bare remote; with a bogus remote, DecideResult has pushed:false and pushError, and the local note still exists.

**Routes (scoped mount; memory graphs → 400 `{ error: "git review is only available for repo graphs" }`):**
- `GET /git/proposals` → `{ proposals: GitProposal[] }`
- `GET /git/proposals/:sha` → GitProposal | 404
- `POST /git/proposals/:sha/decide` body `{ verdict: "approve" | "reject", by: string }` → DecideResult; KeyMissingError → 409 `{ error: "no signing key for <principal>", code: "key-missing" }`
- `POST /git/proposals/:sha/reviews` body `{ verdict, body, by, comments?: [{ body, anchor, span? }] }` → creates a `review/Review@1` node (attributes verdict/body/commit=sha) through the existing commit path (author = by), then each comment as `review/ReviewComment@1` (attributes body/anchor/span/status) in follow-up changesets with `part_of` edges to the review (endpoints-before-edges per engine facts). Returns `{ reviewId, commentIds, status }` in saved/pending vocabulary.
- `GET /git/proposals/:sha/reviews` → reviews + comments for that sha (query the scoped index: objects of the review types whose commit attribute matches).
- The decide handler resolves the graph entry via the manager (allodGraphId/autoPushNotes/originRemote) and passes it to decideGit.

Tests (app.request(), fixture from Task 1 extracted/shared): 400 memory graph; list + detail shapes; decide approve → note in the scratch repo + second decide shows decided; decide with missing key → 409 code key-missing; review POST → nodes queryable via GET with correct commit binding and saved/pending status honesty.
